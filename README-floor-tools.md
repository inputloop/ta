# Floor tools: the install

Author: Corwin Brust <corwin@bru.st> · Prose: CC BY 4.0 · Code: GPL-3.0-or-later (each file says so, or `REUSE.toml` does) · How to check this install: run `sh bin/floor-selftest.sh` and compare `SOURCES.tsv` with `sha256sum`.

This folder holds seven checking tools, copied from the 2026-09-30 turn into one `bin/`. Their tests and fixtures are in `tests/<tool>/`, plus a new `bin/floor-selftest.sh` that runs every tool's own self-test. To install into a project, copy `bin/` to the project's `bin/` and `tests/` to a `tests/` folder **beside** it. settle.py and floor-selftest.sh look for `../tests/` relative to `bin/`. Every tool here answers in the house's three answers: **0** OK, **1** RED (it found a fault), **77** NOT CHECKED (it could not see, and says so instead of going green). Some tools add a usage answer (2 or 64), and the consent gate adds a fourth answer, PARK. Below, "Observed" means I ran it and the receipt is named. "Read" means I only read the code, and it is not proven. Each concern carries a tag and a way to show it wrong.

## The tools

**three_answers.py** (`bin/three_answers.py`) is the gauge for the convention itself. It asks other tools the same question over an empty input, a known-good input and a known-bad input, and says whether each answers honestly, in particular whether any goes green over nothing. Self-test: `python3 bin/three_answers.py --prove-red --workdir DIR`. It plants six fake tools (honest, blind, crashing, words-only, skip-row, dependency-missing), and answers 0 only if each is classified as planted, a deliberately wrong expectation table is caught, and an empty tool list answers 77. Real use: `python3 bin/three_answers.py census TOOLS.tsv --out census.tsv --workdir DIR`. That answers 0 when every primary row was anchored and none is green-when-blind or broken, 1 when one is, 77 when no row ran or a row could not be anchored, and 2 for usage. Observed: self-test answered 0 under all three invocations (`receipts/step-b/2-after-settle-fix/three_answers.py.*.out`). Limits: [MINE] without `--workdir` it writes `work/` beside itself, into `bin/` (source line 63). Falsifier: run it without the flag and see `bin/work/` appear. [MINE] Read, not run: census mode looks for its fixtures in `bin/fixtures` (`$FX`, source line 217), and `tests/three_answers/tools.tsv` also needs `roots-snap.tsv` and `/home/claude/snap` from the turn. So the copied tool list will not run from this install as it stands; only the self-test is proven here. Falsifier: `census tests/three_answers/tools.tsv` from the install giving anchored rows. Not planted in step D.

**owner_check.py** (`bin/owner_check.py`, v0.2) asks "whose rule is this, and can the record show it?" It finds sentences that hand a rule to the keeper ("Corwin wants", "his rule", a heading "What Corwin wants") and requires each to locate: a quoted span of four or more words found word for word in a declared source, or the sentence itself in an owner:HIS part. It also renders instruction files from parts and says whether a copy is CURRENT, STALE or LOCAL. Self-test: `python3 bin/owner_check.py --prove-red`, observed 18 plants red and 12 controls clean under all three invocations. Real use: `python3 bin/owner_check.py scan FILE... --parts P --source S`, or `check RENDERED --parts P`, or `render PARTS... -o OUT`. It answers 0 when clean (no UNLOCATED, copy CURRENT or LOCAL), 1 when it flags (UNLOCATED, STALE), 2 for usage, a refused render or an unreadable file, and 77 when nothing was checked. Limits, from its own header: the attribution patterns and the four-word floor are its author's (4 is an invented house number), and a phrasing its patterns miss is not checked. It trusts an owner:HIS part as his and cannot prove authorship. [MINE] Read, not run: one self-test control pipes to `sha256sum`. Without that program the control reads dirty and the answer is 1, not 77, so floor-selftest checks for `sha256sum` first. Not planted in step D.

**settle.py** (`bin/settle.py`) settles a sealed checkpoint of called shots against a results file and reports the Brier score. Self-test: `python3 bin/settle.py --prove-red`, observed "12 of 12 held" under all three invocations after one fix. Real use: `python3 bin/settle.py CHECKPOINT.md RESULTS.tsv --seal HEX [--results-seal HEX] [--base DIR] [--roots ROOTS.tsv]`. It answers 0 when at least one shot was scored and nothing is RED. It answers 1 for an unsealed or edited checkpoint, a receipt that does not resolve, results edited after their seal, a result for a shot never called, or a duplicate or malformed row. It answers 77 when nothing could be scored, and 2 for usage or a missing self-test fixture. **Changed in this install** (one line, `receipts/settle-fix.diff`): as copied, the self-test answered 2 "fixture missing: install/bin/fixtures/checkpoint-good.md" under all three invocations (`receipts/step-b/1-as-copied/`). Line 329 now also looks in `../tests/settle/fixtures`. Limits: [MINE] the self-test makes its scratch folder inside `bin/` and keeps it there if it fails, so `bin/` must be writable (source line 335). Falsifier: a read-only `bin/` making the self-test fail. Second-reader survivors (step D, `SECOND-READER.tsv`): **S-A**, a receipt pointing at a real, non-blank line that has nothing to do with the shot is scored as settling it. **S-B**, the self-test never plants a probability outside 0..1, so switching that check off goes unnoticed (the tool itself does refuse p=1.50). Caught: **S-C**, a second called-shot table.

**drift_line.sh with drift_line.awk** (`bin/drift_line.sh`; the `.awk` must stay beside it) appends a drift checkpoint line to a log only if the line can say no. It must name the thing pushed back on, or the literal `NONE`, and say who graded it. A refused line leaves the log untouched. Self-test: `sh bin/drift_line.sh --prove-red`, observed "22 of 22 held" under all three invocations. Real use: `sh bin/drift_line.sh append LOG yes|no OBJECT PUSHED_BACK|NONE self|other:WHO NOTE`, `sh bin/drift_line.sh check [FILE]`, and `sh bin/drift_line.sh audit [--legacy] LOG...`. It answers 0 when every line is accepted, 1 when one is refused, 2 for usage, and 77 when no line was read. Limits: its own header says the "concrete thing" test is lexical and cannot tell a true object from a plausible one. [MINE] the self-test, too, makes its scratch folder inside `bin/`. Second-reader survivors: **D-A**, a line with Windows (CRLF) line endings and an empty note is accepted, though the same line with plain line endings is refused. **D-B**, an impossible time stamp (2026-19-39T29:59Z) fits the pattern and is accepted. **D-C**, the self-test's only bad stamp is the word "yesterday", so loosening the stamp check to "starts with a digit" goes unnoticed.

**cases-check.sh** (`bin/cases-check.sh`) reads a precedence-case register back in words, row by row. It counts only rows that are recorded (not constructed) and where the org's rule and the person's instruction disagreed, so a made-up example can never flip a default that waits on "the first recorded case". Self-test: `sh bin/cases-check.sh --prove-red tests/cases-check/cases.tsv`, observed OK under all three invocations. The register in `tests/cases-check/` holds three constructed rows from the Emacs AGENTS.md case and counts none of them. Real use: `sh bin/cases-check.sh check REGISTER.tsv`. It answers 0 when well-formed and prints the count line (NO CASE, ORG-WINS, ORG-FIRST, EQUALS or PERSON-WINS), 1 when a row is malformed (FLAG), 77 when the register is missing or unreadable, and 2 for usage. Limits: [MINE] it does not check that a receipt cell points anywhere. Its own case m8 accepts the made-up `some/receipt#L1` on purpose (source lines 95-96). Falsifier: a design note saying receipts are resolved elsewhere. A register saved with Windows line endings is refused, but the flag says "header is not the register header" rather than naming the line endings (step D, C-C, caught). Second-reader survivors: **C-A**, a recorded row dated "not-a-date" is counted. **C-B**, the self-test never empties the org-rule cell, so switching off that check goes unnoticed (the tool itself does flag it).

**paper-citations.py** (`bin/paper-citations.py`) checks a paper's citations both ways. Forward, every cited entry id must exist as a `### <id>:` heading in the file its prefix maps to. Back, it lists which paper sections cite each source file. Self-test: `python3 bin/paper-citations.py --prove-red`, observed "good->0 bad->1 empty->77" under all three invocations. Real use: `python3 bin/paper-citations.py PAPER.md --root TURN_DIR [--journal JOURNAL.md] [--out CITATIONS.md]`. It answers 0 when all citations resolve, 1 when one is MISSING, 2 for usage, and 77 when the paper cites no entry id. Limits: [MINE] the folder layout of the 2026-09-30 turn (act1/r1, r2, r3, act2) and four named sources are written into it, so a paper laid out differently will read MISSING (read). Falsifier: such a paper resolving. Observed: its self-test leaves its temporary folder behind, one per run (three after three runs, `receipts/step-b/1-as-copied/leftovers.txt`). floor-selftest contains this by giving every tool its own temp folder and removing it. Observed: when a missing id is cited twice, the summary counts it as two distinct ids (`receipts/step-d/P-A.out`, control run); the exit is still right. Second-reader survivors: **P-A**, a paper kept under `act2/` that holds its own `### L1X-001:` heading resolves its own citation, so it can be its own source. owner_check.py already refuses that. **P-B**, the self-test cites only two of the five id families, so breaking the mapping for P-ids goes unnoticed.

**The consent gate** (`bin/consent_check.sh`, with `consent_check.awk` and `consent_prove_red.sh` beside it, and its specification `bin/SPEC-consent.md`) is Act I's P7B gate, rebuilt from a fresh SPEC. It decides whether a signed consent record may unblock the one action it names. Self-test: `sh bin/consent_check.sh --prove-red`, observed "56/56 plants exited as expected" under all three invocations. Its separate mutation test, `tests/consent_check/mutants_consent.py`, killed 11 of 11 when run beside the installed gate (`receipts/tests-runners/consent-mutants.out`). Real use: `sh bin/consent_check.sh --record REC --sig SIG --allowed-signers ALLOW --source-keys F [--now ISO] [--session-end ISO] [--keeper PRINCIPAL] [--seen F]`. It has four answers, not three: 0 PASS. 1 FAIL, the record cannot authorize anything as written. 2 PARK, the record is intact but the action is held, which is the skill's CLAUD_QA_HOLD. 77 NOT CHECKED, evidence it needed was not given or could not be computed. Usage is 64. It needs `awk`, `ssh-keygen` and `sha256sum`; without `ssh-keygen` its self-test says 77 itself (read, `consent_prove_red.sh` line 11). Limits, from its SPEC: it was written without `VERIFY-CONSENT.md`, which the skill names but the snapshot lacked. Not planted in step D, since it already carries 56 plants and 11 mutants. Two [MINE] choices for him: `SPEC-consent.md` sits in `bin/` because the gate names it by bare file name, and it is stamped GPL-3.0-or-later because the brief said every file. The house rule would make a prose SPEC CC BY 4.0, so that is a fork for him to call.

**floor-selftest.sh** (`bin/floor-selftest.sh`, new) runs all seven self-tests above, with the interpreter each needs, from any folder. It prints one line per tool in plain words, then a summary. Command: `sh bin/floor-selftest.sh` (add `--keep DIR` to keep every tool's full output). It answers 0 when every self-test answered 0 and printed its own pass line. It answers 1 when any self-test answered something other than 0 or 77, answered 0 without its pass line, or a tool file is missing. It answers 77 when nothing went RED but a tool could not run here: python3, awk, ssh-keygen or sha256sum is missing (it names the tool and the program), or the tool's own self-test said 77. RED outranks NOT CHECKED. No installed tool needs perl today. Observed: 0 with 7 of 7 passed, under all three invocations (`receipts/step-c/floor-selftest.*.out`). With python3 hidden from PATH it answered 77, naming the four Python tools (`receipts/step-c/floor-selftest.no-python3.out`). Its own self-test, `sh bin/floor-selftest.sh --prove-red`, runs nine throwaway copies of the install, and answered 0 with 9 of 9 cases as they must be. Those cases cover a stub exiting 1, a stub exiting 2, a stub exiting 0 silently, a stub saying 77, python3 hidden, awk hidden, python3 hidden together with a red stub (answers 1), and a tool file removed. Four mutants of floor-selftest itself were each caught by that self-test (`receipts/step-c/floor-selftest-mutants.out`). Limit, a survivor of my own (**F-A**): the pass-line check is a word match. A stub that prints "prove-red: 0 of 0 held" and exits 0 is reported as passed (`receipts/step-c/floor-limit-words-stub.out`). The SPEC that would catch it is in `SECOND-READER.tsv`.

## What else is here

`SOURCES.tsv` has one row per installed file: where it came from, both sha256 sums, and whether it changed and why. 18 files changed, each only by an SPDX line appended as the **last** line, so a `file:line` receipt cut against the source still lands on the same line here. settle.py also has its one-line fix. 299 files are byte-identical: 5 already carried the line, and 294 cannot take one without breaking (a JSON file, a header-on-line-1 register, signed records). Those 294 are licensed by `REUSE.toml`. `SECOND-READER.tsv` is step D in a table: twelve plants, eleven called before running (`receipts/step-d/CALLED-before-plants.txt`), and every survivor with the one-line SPEC that would catch it. `receipts/` holds the scripts that made all of this and every output they wrote, each with its command on the first line. The two mutation runners in `tests/` (`tests/settle/mutants.py`, which also covers drift_line, and `tests/consent_check/mutants_consent.py`) expect to sit beside the tools they mutate. Run them in a throwaway copy, as `receipts/tests-runners/` shows (20 of 20 and 11 of 11).
